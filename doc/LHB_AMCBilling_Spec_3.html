Module Overview

The AMC Billing module manages Annual Maintenance Charge billing for all LHC and CP agreements — covering invoice generation, day-end file exports (SQL Account + email blast), and individual invoice download. Payment is handled externally in SQL Account.

Two billing systems, one module. LHC (cocode 03/15) uses amc_mem for billing schedules and CP (cocode 02) uses ps_amc_mem. Both feed into ac_amcbill. Payment is handled externally in SQL Account — no payment functionality in this module. Day-end files are generated for SQL Account import and Mailgun email blast.

Key Structure Confirmed from Source Data + Invoice PDF

Each billing year generates up to 4 invoice records in ac_amcbill, but the printed/emailed invoice shows 2 line items + tax (confirmed from invoice PDF):
  • A prefix → Main AMC invoice — shown on invoice (e.g. MYR 560.82)
  • K prefix → Sinking Fund — shown on invoice (e.g. 10% = MYR 62.31)
  • S prefix → Service Tax record — shown on invoice as Service Tax 8% (e.g. MYR 44.87)
  • Y prefix → Rounding adjustment — CP only
Invoice total = AMC + Sinking Fund + Service Tax + Rounding = MYR 668.00 (2026 rate, cocode 03/15)
bill_type confirmed values (corrected from AMC_Module.txt):
  • N = Normal billing (standard annual)
  • A = Advance billing — billed when member uses advance year entitlement
  • H = Ad-hoc billing — for agreements that were SU or PT and have been reactivated; generates missed billing from where it stopped
  • F = Final year billing — last AMC billing, generated on agreement anniversary month

lock_status field — recommendation for new system:
In Informix, lock_status (U=Unlocked, L=Locked) was used to handle concurrent multi-user record editing in a client-server environment. In the new web-based system, this is no longer needed — the web framework handles concurrency natively via database transactions, row-level locking, and HTTP session management.

Recommendation: Drop lock_status from all new tables. For migrated records, the field is still present in Informix source data (always U in active records) but adds no value in the new system. The amc_price and amc_price_points tables use lock_status = U/E to distinguish active vs expired rates — this is replaced by the effective_date ordering logic (latest active record = current rate).
